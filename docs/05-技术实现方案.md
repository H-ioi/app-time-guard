## 5.2 关键技术与职责

| 组件 | 职责 | 关键 API |
| --- | --- | --- |
| 规则引擎 | 状态机驱动（可用/提醒/冷却/锁定），规则匹配与最严格结算 | 本地纯逻辑模块，可单元测试 |
| 管控服务 | 前台服务常驻；绑定无障碍/通知监听；定时心跳 | Service + START_STICKY + 厂商保活 |
| 无障碍服务 | 拦截被禁 App 启动（TYPE_WINDOW_STATE_CHANGED 监听 + 包名判定）；叠加锁定界面 | AccessibilityService |
| 设备管理员 | 锁屏、设置/清除锁屏密码、防卸载（Owner）、禁多用户/开发者（Owner） | DevicePolicyManager |
| 使用统计 | 每日使用时长、App 时长、解锁次数 | UsageStatsManager / UserUsageStatsService |
| 时间可信 | 用单调时钟检测时间篡改、维护偏移基准 | SystemClock.elapsedRealtime() + 自研偏移检测 |
| 投屏检测 | 检测外部显示/无线投屏连接，投屏期间息屏按使用中结算（见 02 章 2.2.4） | DisplayManager.registerDisplayListener + MediaSession 播放状态启发式；华为 Cast+/多屏协同真机验证 |
| 数据存储 | 规则、状态、统计、日志 | Room（本地 SQLite）+ DataStore |
| 安全存储 | PIN、密钥 | Android Keystore + EncryptedSharedPreferences |
| 通知 | 提醒、告警、家长通知 | NotificationChannel + NotificationListenerService |
| 拦截/锁定 UI | 全屏锁定界面（FLAG_SECURE 防截屏） | Activity + 无障碍叠加层双保险 |

## 5.3 核心流程（示例）

### 5.3.1 App 启动拦截
```
孩子点击"游戏"图标
  → AccessibilityService 捕获 TYPE_WINDOW_STATE_CHANGED（包名=游戏）
  → 规则引擎查询：当前状态（可用/冷却/锁定）+ 应用范围（是否禁止）
  → 禁止：显示全屏拦截提示（含"请求家长"入口）
  → 允许：放行，同时启动该 App 使用计时
```

### 5.3.2 用停交替结算
```
单次使用达到 X 分钟（或全局配额/单次上限耗尽）
  → 孩子端弹"时间到"缓冲（默认 5 分钟，可配置 0）
  → 缓冲结束 → 进入冷却态：全屏休息界面 + 持久化冷却结束时间戳
  → 冷却满 Y 分钟（以可信时间校验）→ 自动恢复可用
```

### 5.3.3 时间篡改检测（纯本地，无网络依赖）
```
系统时间 System.currentTimeMillis() 可被用户修改，而 SystemClock.elapsedRealtime()
（自开机以来单调递增）用户无法修改，只会被重启清零。
  → 维护偏移量 offset = 系统时间 - elapsedRealtime
  → 检测到 offset 明显回拨（超过阈值，如 5 分钟）→ 判定"时间回拨"
  → 配额结算一律基于单调时间，杜绝"改时间重置配额"
  → 重启后以开机时刻重建基准，仍可检测"回拨到过去"式篡改
  → 判定篡改后按最保守规则结算，并标记异常上报家长 + 审计
```

## 5.4 数据模型（概要）

```
Rule（规则）           ：id, weekdayMask, startMin, endMin, mode, scopeType, ...
Scope（应用范围）       ：白名单/黑名单/分类/例外清单
Limit（时长限制）       ：dailyQuota, continuousMax, useX, restY, appLimits(Map<pkg,min>)
Action（动作）          ：remindLeadMinutes, lockStyle, allowSaveBuffer, ...
QuotaState（配额状态）  ：date, usedMinutes, perAppUsed(Map), resetTime
AuditLog（审计日志）    ：ts, type, detail
Settings（设置）        ：pinHash, biometricOn, trustedTimeOffset, securityLevel, ...
```

## 5.6 兼容性要求

- 最低 Android 8.0（API 26），目标 14（API 34）适配 15；
- 厂商兼容：华为/小米/OPPO/vivo/荣耀 后台保活白名单引导页；
- 分屏/画中画：锁定态禁止进入；
- 折叠屏/平板横竖屏：锁定与统计 UI 自适应。

### 5.6.1 华为平板专项适配（Android 版 · HarmonyOS 2/3/4.x 兼容安卓版）

本节约定 **Android 版**在华为平板（HarmonyOS 兼容安卓版）上的适配要求。华为平板为本产品重点设备（如 MatePad 系列）：

| 项 | 要求 |
| --- | --- |
| 系统兼容 | 覆盖 HarmonyOS 2/3/4.x（兼容安卓应用）；HarmonyOS 基于 AOSP，无障碍、使用统计、设备管理员等标准 Android 权限机制均可用，但需逐型号真机验证 |
| NEXT 设备 | HarmonyOS NEXT（5.x）不兼容 APK，不属本节约束范围，见 5.9 独立版本方案 |
| 无 GMS 依赖 | 华为平板无 Google 服务，App 不得依赖任何 GMS 组件（本产品纯本地离线，天然满足）；不得检查 Google Play 服务是否存在 |
| 后台保活 | 引导家长将 App 加入「设置 > 应用 > 应用启动管理」手动管理（允许自启动、关联启动、后台活动），否则服务易被清理导致管控失效 |
| 电池优化 | 引导关闭「电池 > 更多电池设置」中耗电限制/智能省电对 App 的限制 |
| 纯净模式 | HarmonyOS 纯净模式默认仅允许应用市场来源安装，侧载需家长关闭；上架 AppGallery 可免除此步 |
| 应用分身 | 识别并默认禁止分身包名；引导家长关闭「设置 > 应用 > 应用分身」 |
| 投屏/多屏协同 | 华为无线投屏（Cast+）、多屏协同、超级终端是否触发 DisplayListener 外部显示回调需逐型号真机验证；验证通过者走"投屏计为使用"策略（02 章 2.2.4），未通过者用"息屏 + 音频播放"启发式兜底 |
| 多用户/访客 | 设备所有者模式下禁用多用户/访客模式，防止切换用户绕过管控 |
| 锁屏方式 | 平板无指纹型号依赖 PIN/密码；锁定界面与系统锁屏的兼容性需真机验证 |
| 紧急应用 | 平板无蜂窝通话，就寝模式的"紧急通话"改为家长指定的紧急应用（如网络电话） |

### 5.6.2 分发与安装（华为）

- 正式分发：上架华为应用市场（AppGallery），需提供隐私政策与软著等材料（纯本地 App 隐私政策简单）；华为审核要求 targetSdk 版本需满足其时限政策；
- 侧载安装：家长关闭纯净模式后安装 APK，设置向导中提供图文引导；
- 交付方式：MVP 阶段以 APK 侧载为主，正式版再上架 AppGallery。

## 5.8 技术风险与对策

| 风险 | 影响 | 对策 |
| --- | --- | --- |
| 厂商杀后台导致服务被杀（华为尤甚） | 管控失效 | 前台服务 + 华为"应用启动管理"引导 + 开机自检恢复（见 5.6.1） |
| 无障碍在某些 ROM 上被自动关闭 | 拦截失效 | 监测 + 告警 + 一键修复引导 |
| 设备所有者激活门槛高 | 防卸载能力弱 | 提供 adb 图文教程；非 Owner 模式降级告警方案 |
| 统计口径与家长认知偏差 | 信任问题 | 统计口径文档化 + 界面解释（如"通话不计入"） |
| 无联网下无法核对真实时间 | 孩子改系统时间延长使用 | 单调时钟偏移检测 + 最保守结算 + 篡改告警留痕（见 5.3.3） |
| 投屏息屏绕过 | 息屏观看电视内容不消耗配额 | 显示监听 + 投屏计费策略 + 音频播放启发式兜底（见 02 章 2.2.4、T14） |
| 纯净模式阻止侧载安装 | 安装受阻 | 上架 AppGallery 或引导关闭纯净模式（见 5.6.2） |
| 华为各型号权限行为差异 | 功能不可用 | 主流型号（MatePad 系列）真机矩阵测试，覆盖 5.6.1 全部专项项 |
| Android 新版本权限收紧 | 兼容性 | 跟随 targetSdk 升级节奏，建立自动化兼容测试 |
| 双版本维护成本高 | 人力与排期压力 | 共享需求/设计/规则逻辑，管控核心分团队并行；NEXT 版按能力分级排优先级（见 5.9） |
| NEXT 系统能力限制 | NEXT 版强管控不可达 | 能力分级（5.9）：不可达项引导使用华为系统级管控，不硬做 |

## 5.9 双版本架构：Android 版 + HarmonyOS NEXT 版

### 5.9.1 版本定位

| | Android 版 | HarmonyOS NEXT 版 |
| --- | --- | --- |
| 适用设备 | Android 8.0+ 手机/平板；华为 HarmonyOS 2/3/4.x | HarmonyOS NEXT（5.x）平板/手机 |
| 技术栈 | Kotlin + Jetpack Compose | ArkTS + ArkUI（Stage 模型） |
| 管控能力 | 完整（无障碍拦截、防卸载、设备所有者等全量机制） | 能力分级（见 5.9.3） |
| 分发 | APK 侧载 / AppGallery | 上架华为应用市场（HAP） |

### 5.9.2 为什么不用 uni-app 做双版本（决策记录）

uni-app 可编译 Android 与鸿蒙 NEXT，但本产品**管控核心全部依赖系统级原生 API**（无障碍、使用统计、设备管理、悬浮窗等），跨端框架无法在 JS/TS 层提供这些能力，必须走原生插件/原生模块：

- uni-app 编译 Android：管控核心仍需 Java/Kotlin 原生插件；
- uni-app 编译 HarmonyOS NEXT：产物为 ArkTS 应用，Android 原生插件完全不可用，管控核心需用鸿蒙 API 重写，JS 层仍无法直接调用鸿蒙系统管控 API。

结论：**两版的管控核心都必须原生实现**，跨端框架只能共享 UI 层；而本产品 UI 占比小、管控核心占比大，跨端收益低、桥接与调试成本高。故采用**双原生**：Android（Kotlin）+ NEXT（ArkTS），共享需求文档、UI 设计稿、交互规范与规则引擎逻辑设计。

### 5.9.3 HarmonyOS NEXT 版能力矩阵

NEXT 权限体系与 Android 不同，第三方应用能力受限。按"可实现 / 部分受限 / 不可实现"分级：

| 能力 | 分级 | 说明 |
| --- | --- | --- |
| 家长/孩子双模式 UI、规则配置 | ✅ 可实现 | ArkUI 原生实现，与 Android 版同设计稿 |
| 提醒、缓冲倒计时、锁定界面（本 App 内） | ✅ 可实现 | 全屏窗口 + 前台通知 |
| 规则引擎、配额结算、周计划、报表 | ✅ 可实现 | 纯逻辑，两版共享设计 |
| 使用时长统计 | ⚠️ 部分受限 | NEXT 对全设备应用使用统计 API 开放度有限，需真机验证可读取范围；不可达部分降级为"本 App 内使用时长 + 引导华为系统统计" |
| 拦截受限 App 启动 | ⚠️ 部分受限 | AccessibilityExtensionAbility 可做弱拦截（检测到受限应用后提示/引导退出），强拦截（白名单模式全禁用）受限，需真机验证 |
| 防卸载 | ❌ 不可实现（普通应用） | 依赖华为系统"家长守护/健康使用手机"或企业管控 |
| 全局锁屏防 Home/返回 | ❌ 不可实现（普通应用） | 同上 |
| 禁用设置项/开发者模式/多用户 | ❌ 不可实现（普通应用） | 同上；NEXT 本身不支持多用户切换（天然免疫该绕过） |
| 应用分身 | — | NEXT 已取消应用分身功能（Android 版 T13 威胁在 NEXT 不存在） |

### 5.9.4 NEXT 版产品策略（能力分级落地）

- **原则**：NEXT 版交付"本 App 可实现的全部能力 + 清晰的引导"；
- 强管控部分（防卸载、全局锁定、应用全禁用）**不硬做、不伪造**，在设置向导中引导家长开启华为系统级方案：**「健康使用手机」（应用限额 / 停用时间 / 内容限制）与「家长守护」**；
- 本 App 与华为系统方案**双轨并存**：本 App 负责家长体验统一入口（规则配置 UI、统计报表、提醒），系统方案负责强管控执行；NEXT 版把家长在本 App 的配置，以图文步骤引导其同步到华为系统设置；
- NEXT 版里程碑（M8）验收以 5.9.3 能力矩阵内"可实现"项全部通过为准。
