# 02 控制机制需求（核心）

本文档是整套需求的**核心**：定义产品的控制机制全景、规则引擎模型、每种控制方式的详细行为，以及多条规则同时生效时的组合与优先级。

## 2.1 控制机制全景图

产品提供 **4 大类、13 种控制机制**，可自由组合：

| 大类 | 机制 | 一句话说明 |
| --- | --- | --- |
| A 时长类 | A1 每日总时长配额 | 每天最多用多久，用完当天锁定 |
| A 时长类 | A2 连续使用上限 | 单次最长连续使用，防止"一玩到底" |
| A 时长类 | A3 用停交替（番茄钟式） | 用 X 分钟 → 必须休息 Y 分钟 → 才能继续 |
| A 时长类 | A4 按应用独立限时 | 不同 App 各自的每日时长 |
| A 时长类 | A5 奖励/临时时长 | 家长额外给时间（奖励、应急） |
| B 时间类 | B1 可用时间段 | 每天允许使用的时间窗口（可多段） |
| B 时间类 | B2 就寝模式 | 夜间固定时段全设备锁定 |
| B 时间类 | B3 周计划 | 按星期几应用不同规则 |
| B 时间类 | B4 假期模式 | 一键切换"上学日/周末/假期"方案 |
| C 应用类 | C1 全禁用 + 白名单 | 只允许指定 App，其余全部禁开 |
| C 应用类 | C2 黑名单 | 禁止指定 App 启动 |
| C 应用类 | C3 分类限制 | 按类别（游戏/视频/社交/商店）批量禁用 |
| C 应用类 | C4 作业/专注模式 | 固定时段内仅学习类 App 可用 |
| D 干预类 | D1 一键锁定/暂停 | 家长立即锁定或暂停当前规则 |
| D 干预类 | D2 临时放宽 | 家长临时开放指定 App 一段时间 |

> 说明：用户原始 3 点需求对应关系 —— ①"每天总时长 + 用满须停"= A1+A2/A3；②"可用时间段 + 应用限制"= B1+C1/C2/C3；③"禁用所有 App 仅开放部分"= C1。

## 2.2 规则引擎模型

### 2.2.1 规则 = 时间窗 × 应用范围 × 时长限制 × 干预动作

每条控制规则由四个维度组合而成：

```
规则 Rule
├── 生效时间 Window
│   ├── 星期几（周一~周日，可多选）
│   ├── 起止时段（如 19:00-21:00，可多段）
│   └── 模式类型（普通时段 / 就寝时段 / 专注时段）
├── 应用范围 Scope
│   ├── 全部应用
│   ├── 白名单（仅允许这些）
│   ├── 黑名单（禁止这些）
│   ├── 按类别（游戏/视频/社交/购物/商店/浏览器…）
│   └── 系统设置类（禁用应用商店、浏览器等）
├── 时长限制 Limit
│   ├── 每日总时长配额（分钟）
│   ├── 单次连续使用上限（分钟）
│   ├── 用停交替（用 X / 停 Y，分钟）
│   └── 按应用独立配额（App → 分钟/天）
└── 干预动作 Action
    ├── 提前提醒（剩余 5/10 分钟提醒）
    ├── 到期动作（锁定 / 仅提醒）
    ├── 锁定形态（全屏拦截 / 系统锁屏 / 提示条）
    └── 退出方式（家长 PIN / 自动到点解锁）
```

### 2.2.2 关键概念

- **配额池（Quota Pool）**：系统实时维护"今日已用时长 / 今日剩余时长"。任何时长类规则消耗同一个配额池；多个时长限制同时生效时，按**最严格**结算（见 2.4）。
- **使用状态机**：设备在每个时刻处于四种状态之一——`可用`、`提醒中`（缓冲倒计时）、`冷却中`（休息/配额耗尽）、`锁定中`（禁止使用）。状态流转由规则引擎自动驱动。

```
        ┌─────────┐  到配额/单次上限/用满X   ┌─────────┐
        │  可用    │ ─────────────────────▶ │ 提醒中   │（缓冲倒计时，如5分钟）
        └─────────┘                        └─────────┘
             ▲                                  │ 缓冲结束
             │                                  ▼
        ┌─────────┐                        ┌─────────┐
        │  冷却中  │ ◀───────────────────── │  锁定中  │
        │(休息/等待)│   休息满Y/到点自动解锁     │         │
        └─────────┘                        └─────────┘
```

- **统计口径**：`使用时长` = 屏幕点亮且处于可用状态的累计时长（非锁屏、非系统界面）**，加上"投屏使用时长"**（见 2.2.4）；`休息时长` = 冷却/锁定状态时长。统计口径对家长可见、可解释，避免"为什么我用了 2 小时"的争议。

### 2.2.4 投屏场景（息屏投屏电视 / 多屏协同）

孩子可能将平板投屏到电视后息屏观看，此时屏幕关闭、系统判定应用"不在前台"，若不特殊处理则**不消耗配额**，形成绕过。

| 项 | 处理 |
| --- | --- |
| 默认策略 | **投屏计为使用**：检测到投屏连接期间，即使平板息屏，也按"使用中"结算配额（计入总时长、消耗每日配额） |
| 检测目标 | 镜像投屏（无线投屏/Cast+）、应用级投屏（视频 App 投电视）、华为多屏协同/超级终端 |
| 家长可选策略 | ① 投屏计为使用（默认）；② 投屏即锁定（严格模式，检测到投屏直接进入冷却/锁定）；③ 允许投屏不计数（仅当家长明确认为"看电视不算平板使用"，默认关闭） |
| 检测不完整时 | 无法检测到的投屏形态（如部分私有协议）降级为"音频播放中 + 息屏"启发式补判，仍按使用中结算；设置向导中如实说明"极少数投屏方式可能无法识别"，避免家长误以为完全覆盖 |

### 2.2.3 规则生效的边界条件

- 规则按**当前时刻**匹配：星期几 + 时刻都命中才生效；多条规则同时命中进入 2.4 组合逻辑。
- 时间窗口跨天（如 22:00-02:00 就寝）：按"开始时间所在日"归属。
- 配额**按自然日重置**（家长可配置重置时刻，默认 0:00）。
- 设备重启、断网不影响规则执行（规则本地存储、本地执行）。

## 2.3 各控制机制详细需求

### 机制 A1：每日总时长配额（用户需求点 1 的前半）

| 项 | 说明 |
| --- | --- |
| 定义 | 一天内允许使用设备的总时长上限，用满即当天锁定 |
| 可配置参数 | 配额时长（5~600 分钟，步长 5）、重置时刻（默认 0:00）、到期动作 |
| 交互行为 | 剩余 10/5/1 分钟时弹提醒；剩余 0 进入冷却 |
| 冷却策略 | 默认"用完即锁到次日重置"；可配置"冷却 N 分钟后恢复"（配额耗尽后停 N 分钟可继续小额使用） |
| 示例 | 每天 90 分钟；用到 85 分钟收到提醒，90 分钟设备锁定，次日 0:00 解锁 |

### 机制 A2：连续使用上限

| 项 | 说明 |
| --- | --- |
| 定义 | 单次最长连续使用时长，到点强制休息，防"一玩到底" |
| 可配置参数 | 连续上限（5~120 分钟）、休息时长（1~60 分钟） |
| 交互行为 | 连续使用达上限 → 进入冷却（必须休息满 N 分钟）→ 恢复可用 |
| 与 A1 关系 | 同时配置都生效：A2 管"单次"，A1 管"全天" |
| 示例 | 连续上限 30 分钟：玩 30 分钟强制休息 10 分钟，全天最多累计 90 分钟 |

### 机制 A3：用停交替（番茄钟式，用户需求点 1 的核心）

| 项 | 说明 |
| --- | --- |
| 定义 | 使用 X 分钟，必须停止/休息 Y 分钟，才能继续使用 X 分钟 |
| 可配置参数 | 使用时长 X（5~60 分钟）、休息时长 Y（1~60 分钟）、休息是否计入配额（默认不计入） |
| 交互行为 | 用满 X → 提醒 → 锁定 Y 分钟 → 自动恢复；休息倒计时在孩子端界面常驻显示 |
| 灵活增强 | ① 冷却恢复制：配额耗尽后"停 Y → 恢复 N"循环；② 首段豁免：每天第一次使用可跳过休息（可配置） |
| 示例 | X=20、Y=20：玩 20 分钟 → 强制休息 20 分钟 → 再玩 20 分钟，全天配额 120 分钟 |

### 机制 A4：按应用独立限时

| 项 | 说明 |
| --- | --- |
| 定义 | 不同 App（或 App 分组）各自的每日时长上限，互不共享 |
| 可配置参数 | 每个 App/分组：每日上限（5~600 分钟）或"不限" |
| 交互行为 | 某 App 配额耗尽 → 该 App 被拦截，其他 App 不受影响 |
| 组合规则 | 应用级配额与全局配额同时生效时，取先耗尽者（都算超时） |
| 示例 | 游戏 App 30 分钟/天，视频 App 60 分钟/天，学习 App 不限 |

### 机制 A5：奖励/临时时长

| 项 | 说明 |
| --- | --- |
| 定义 | 家长在孩子表现好或临时需要时，额外增加使用时长 |
| 操作 | 家长模式 → 一键「+15 分钟」（可选 5/10/15/30/60） |
| 效果 | 向当前生效的配额池追加时长，立即生效 |
| 限制 | 追加时长仅当日有效；家长可设置"奖励后当日配额上限"防止失控 |

### 机制 B1：可用时间段（用户需求点 2 的前半）

| 项 | 说明 |
| --- | --- |
| 定义 | 每天只在指定时间段内允许使用，其余时间锁定 |
| 可配置参数 | 每天可设 1~4 个时间段（如 16:00-18:00、19:00-21:00）；按星期区分 |
| 交互行为 | 时间段外 → 锁定（显示"使用时间已结束"）；时间段内且配额未用完 → 可用 |
| 边界 | 段与段之间、跨天时段；时间未到提前解锁视为异常并记录 |
| 示例 | 工作日 19:00-21:00 可用；19:00 解锁、21:00 自动锁定 |

### 机制 B2：就寝模式

| 项 | 说明 |
| --- | --- |
| 定义 | 夜间固定时段全设备锁定（含白名单 App），守护睡眠 |
| 可配置参数 | 起止时间（如 21:30-07:00）、是否允许指定"紧急应用"（平板无蜂窝通话，紧急应用指家长指定的网络电话/常用 App）、锁定界面是否显示时钟 |
| 交互行为 | 到点强制锁定；期间解锁需家长 PIN；到点自动解锁 |
| 示例 | 21:30 自动锁定，显示"晚安"时钟界面，7:00 自动恢复 |

### 机制 B3：周计划

| 项 | 说明 |
| --- | --- |
| 定义 | 按星期几配置不同的规则方案，最常见的灵活用法 |
| 可配置参数 | 每个星期几独立配置一套规则；支持"复制到其他天" |
| 交互行为 | 自动按当天星期几生效 |
| 示例 | 周一~周五：90 分钟 + 19:00 后；周六日：150 分钟 + 自由时间段 |

### 机制 B4：假期模式

| 项 | 说明 |
| --- | --- |
| 定义 | 预设多套方案（上学日/周末/假期），一键切换，避免临时手忙脚乱 |
| 可配置参数 | 方案列表（每套含完整规则）；当前生效方案；假期开始/结束日期（可选，到期自动切回） |
| 示例 | 暑假前设好"假期方案：150 分钟/天"，开学日自动切回"上学日方案" |

### 机制 C1：全禁用 + 白名单（用户需求点 3）

| 项 | 说明 |
| --- | --- |
| 定义 | 除白名单外的**所有** App 一律无法启动（设备变"学习机"） |
| 可配置参数 | 白名单 App 列表（单个添加 / 按类别整批添加） |
| 交互行为 | 非白名单 App 启动 → 拦截并提示"该应用已被家长限制" |
| 系统例外 | 系统电话/紧急拨号（手机端）、紧急应用（平板端，家长指定）、必要系统项（可配置）不受影响 |
| 示例 | 白名单=网课、词典、计算器；孩子打开游戏 → 被拦截 |

### 机制 C2：黑名单

| 项 | 说明 |
| --- | --- |
| 定义 | 仅禁止指定 App，其余 App 正常使用 |
| 可配置参数 | 黑名单列表；黑名单/白名单两种模式互斥，一次只启用一种 |
| 示例 | 黑名单=某短视频、某游戏；其余 App 不受限 |

### 机制 C3：分类限制

| 项 | 说明 |
| --- | --- |
| 定义 | 按应用类别批量禁用（游戏/视频/社交/购物/商店/浏览器/阅读…） |
| 可配置参数 | 类别开关；类别可整体加入白名单或黑名单 |
| 分类来源 | 预置分类库（按包名映射），家长可手动修改单个 App 类别 |
| 示例 | 开启"禁游戏、禁视频"：所有被归类的游戏/视频 App 全部禁用 |

### 机制 C4：作业/专注模式

| 项 | 说明 |
| --- | --- |
| 定义 | 指定时段内仅白名单（学习类）App 可用，其余全部禁用 |
| 可配置参数 | 时段、学习类白名单、是否叠加用停交替 |
| 与 C1 区别 | C1 是全局状态；C4 是"时段内临时进入全禁用态"，时段结束自动恢复 |
| 示例 | 周一~周五 19:00-19:40 作业模式：只能打开网课/词典，40 分钟后恢复正常规则 |

### 机制 D1：一键锁定 / 暂停

| 项 | 说明 |
| --- | --- |
| 定义 | 家长立即锁定设备（立即锁定），或暂时停用全部规则（暂停管控，如孩子生病） |
| 操作 | 家长模式 → 立即锁定 / 暂停管控 N 分钟或无限期 |
| 效果 | 立即锁定：全屏锁定直到家长解锁；暂停管控：期间设备不受限制，到期自动恢复 |
| 审计 | 所有干预操作均记录（时间、操作类型），供家长回看 |

### 机制 D2：临时放宽

| 项 | 说明 |
| --- | --- |
| 定义 | 家长临时开放指定 App 一段时间（如聚会时让孩子看动画） |
| 可配置参数 | 目标 App、时长（15/30/60 分钟） |
| 效果 | 到期自动恢复原规则 |
| 示例 | 临时开放"动画片 App" 30 分钟，到期自动重新拦截 |

## 2.4 规则组合与优先级

多条规则同时命中时，遵循以下原则（对家长透明、可预期）：

1. **就寝模式 > 一切**：B2 生效期间，其他规则全部让位，设备锁定。
2. **最严格者优先（时长类）**：同时生效的多个时长限制（全局配额、单次上限、用停交替、应用配额），取**先触发者**执行。例如全局剩 10 分钟、单次上限还有 5 分钟 → 按 5 分钟执行。
3. **应用范围取交集（禁用类）**：白名单/黑名单/分类/专注模式同时生效时，**任一规则判定"禁止"即禁止**；仅当所有规则都允许时才可用。即"禁用的并集、允许的交集"。
4. **时段外锁定优先**：当前不在任何可用时间段内 → 直接锁定，不看时长配额。
5. **家长干预最高优先级**：D1/D2 家长操作覆盖一切规则，但全部留痕，且可设置"自动恢复"。

### 组合示例（家长视角）

| 家长配置 | 实际效果 |
| --- | --- |
| 每日 90 分钟 + 单次 30 分钟 | 每次最多玩 30 分钟，全天累计最多 90 分钟 |
| 19:00-21:00 可用 + 白名单[学习] + 用 20 停 20 | 19:00-21:00 内只能用学习 App，玩 20 分钟休 20 分钟，最晚 21:00 锁定 |
| 黑名单[游戏、视频] + 每日 120 分钟 | 游戏/视频禁开，其余 App 累计 120 分钟/天 |

## 2.5 预设模板（一键套用，降低使用门槛）

| 模板 | 目标 | 默认规则 |
| --- | --- | --- |
| 学龄前（3-6 岁） | 极简 | 每天 30 分钟；用 15 停 15；仅白名单；18:00 前可用；20:30 就寝 |
| 小学生（7-12 岁） | 常规 | 工作日 60 分钟/周末 90 分钟；单次 30 分钟；21:00 就寝；禁游戏/视频 |
| 中学生（13-15 岁） | 宽松 | 工作日 90 分钟/周末 150 分钟；单次 45 分钟；21:30 就寝 |
| 假期模式 | 放松 | 每天 150 分钟；单次 45 分钟；禁游戏（或放开）按家长选择 |

模板可一键套用，套用后家长可继续微调。

## 2.6 临界与异常情况处理

| 场景 | 行为 |
| --- | --- |
| 配额恰好在 App 使用中途耗尽 | 提醒 5 分钟缓冲 → 到期后强制拦截该 App；缓冲内允许保存进度 |
| 时间段开始瞬间 | 自动解锁并弹出"可使用啦"提示（可关闭） |
| 规则修改即时性 | 家长修改规则后**立即生效**（无延迟），并在孩子端可见规则变化提示 |
| 时间被修改/断网 | 见 04 防绕过（时间可信源校准） |
| 配额重置时刻跨天 | 默认 0:00；如家长配置 6:00 重置，则 0:00-6:00 使用量计入前一天 |
| 多 App 同时在前台 | 统计以"当前获得焦点的 App"为准 |
| 投屏使用 | 投屏期间（含息屏）按家长配置的策略结算：默认计为使用、或投屏即锁定、或允许不计数（见 2.2.4） |
